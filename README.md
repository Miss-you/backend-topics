# Backend Topics

一个持续积累的公开后端专题库：把实际遇到的问题、原因、FAQ、契约和验证方法，与经过验证的可复用模块放在一起。

结构参考 [Frontend Topics](https://github.com/Miss-you/frontend-topics)，两者独立维护。当前完成仓库初始化；尚未提供业务后端、运行服务或可复用后端模块，不将待整理方向写成已验证经验。

## 从哪里开始

- [专题索引](docs/topics/README.md)：按问题和机制组织后续案例。
- [FAQ 入口](docs/topics/faq.md)：记录重复问题、原因、适用边界与证据。
- [专题模板](docs/templates/topic.md)：从可复现场景开始整理知识。
- [复盘模板](docs/templates/retrospective.md)：核对已完成、真实遗留项及规则调整。
- [模块约定](packages/README.md)与[示例约定](examples/README.md)：有实际复用与验证后再增加实现。
- [贡献约定](CONTRIBUTING.md)：保持公开内容边界和知识分级。

## 知识分级

| 等级       | 含义                                                 |
| ---------- | ---------------------------------------------------- |
| 已验证契约 | 在明确版本和范围内必须成立的行为，有可失败的验收证据 |
| 条件性建议 | 在写明的前提下有帮助，条件变化时可调整或删除         |
| 待验证问题 | 当前证据不足，明确缺口和验证条件，不当成结论         |

同类问题优先补已有专题与测试；机制不同再新增专题。项目 AGENTS.md 只保留稳定约束和入口链接，案例与取舍留在知识库，不维护两套重复的 AGENTS/CLAUDE 正文。

## 本地检查

Node.js 20+ 用于仓库文档检查，不限定未来模块的后端实现语言。

```sh
npm ci
npm run check
```

当前检查覆盖 Markdown 本地链接和格式，不代表任何业务 API、数据库或部署已经验收。GitHub Actions 执行相同检查。

## 持续积累

遇到问题时，记录可复现场景、已确认原因、解决与代价、失败及恢复边界、测试和不适用条件；然后判断是否需要沉淀模块。每次任务末尾按模板复盘，区分原目标缺口与可选增强，不为填表而制造待办。

当前初始化范围见[首次复盘](docs/retrospectives/2026-11-01-bootstrap.md)。文档、模板与后续原始实现采用 [MIT 许可](LICENSE)；第三方内容保留原有来源与许可。
